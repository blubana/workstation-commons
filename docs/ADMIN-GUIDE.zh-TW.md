# 管理員指南

日常管理都在 **cm-top** 裡完成，不需要直接改系統檔案。每一個管理操作都會寫進稽核紀錄（第 9 頁 Audit）。

## 1. 誰是管理員、怎麼進入

| 角色 | 能做什麼 |
|---|---|
| 擁有者 `user` | 全部；也能 sudo 維護系統 |
| compute 管理員（`computeadmin` 群組） | 在 cm-top 管理使用者、金鑰、kernel、策略、WSL |
| 一般使用者 | 只看自己的用量與 kernel |

進入 cm-top：
- 在伺服器 Windows：開「命令提示字元」輸入 `cm-top`。
- 遠端：`ssh -t -p 2200 user@192.168.1.10 cm-top`（Tailscale：`<tailscale-ip>`）。

按 `1`–`9` 切換頁面，`?` 顯示該頁按鍵，`/` 篩選，`q` 離開。

| 鍵 | 頁面 | 管理用途 |
|---|---|---|
| 1 | Overview | 整體負載、需注意事項 |
| 2 | Users | 建立、停用使用者，角色，金鑰 |
| 3 | Kernels | 所有人的 kernel，可停止 |
| 4 | Policy | 記憶體與 CPU 分配 |
| 5 | Hardware | CPU、GPU、NPU、溫度即時圖（`l`） |
| 6 | WSL | VM 的記憶體、CPU、swap，重啟 WSL |
| 7 | Envs | 共用 Python 環境 |
| 8 | History | 30 天用量歷史 |
| 9 | Audit | 稽核紀錄 |

## 2. 建立使用者

1. 請使用者依《第一次連線》說明產生金鑰，把**公鑰**（`ssh-ed25519 AAAA...` 開頭的一整行）傳給你。只收 `.pub`；有人寄來私鑰，請對方作廢重產。
2. cm-top → `2` Users → 按 `a`。
3. 輸入帳號名稱（小寫英數，例如 `alice`），貼上公鑰，按 Enter 確認。
4. 畫面顯示金鑰指紋（`SHA256:...`）。可請使用者在自己電腦執行 `ssh-keygen -lf ~/.ssh/id_ed25519.pub` 比對，一致就代表沒貼錯。
5. 把帳號名稱告訴使用者。

說明：
- 系統會建立家目錄、`~/data`，並套用記憶體保底與上限。
- 新帳號會清掉同名舊帳號的歷史資料。
- 已存在但不是由 cm-top 建立的系統帳號（以及 sudo、adm 群組成員）會被拒絕，避免誤接管。

## 3. 停用使用者與調整角色

- **停用**：Users 頁選取 → `d` → `y` 確認。會鎖定登入、停止該人所有程式、移除管理員角色。家目錄與資料**保留**。
- **恢復**：對同一帳號再按 `a` 加回，貼上公鑰即可。
- **設為/取消管理員**：選取 → `A`。只給信任的人；管理員可以停掉別人的 kernel、改策略、重啟 WSL。
- 要永久刪除帳號與資料：cm-top 不提供（避免誤刪），由擁有者以 sudo 處理，先備份。

## 4. 管理金鑰

Users 頁選取使用者 → Enter 進入金鑰清單：

| 動作 | 按鍵 |
|---|---|
| 新增金鑰（新電腦） | `a`，貼上公鑰 |
| 移除金鑰（電腦遺失、離職、私鑰外流） | 選取 → `x` → `y` |
| 返回 | `Esc` |

原則：
- 一台電腦一把金鑰，清單中的註解（例如 `alice@laptop`）可分辨是哪台。
- 使用者回報**私鑰可能外流**：立刻移除那把金鑰，請對方重新產生，再加入新公鑰。
- 不要替使用者產生金鑰再傳給他們；私鑰應只在使用者自己的電腦上產生。

## 5. 硬體與資源分配

**策略（`4` Policy → `e` 編輯）**

| 參數 | 目前值 | 意義 |
|---|---|---|
| 保底 MemoryLow | 24 GB / 人 | 別人再忙也不會被搶走的記憶體 |
| 軟上限 MemoryHigh | 72 GB / 人 | 超過會被減速 |
| 總上限 | 88 GB | 所有使用者合計 |
| CPU 合計上限 | 18 核 | 所有遠端使用者合計；另 25% 保留給本機操作者 |
| CPU 權重 | 100 | 所有人相同 |

保底 × 同時活躍人數不要超過總上限，否則保底無法兌現。例如 88 GB 總量、24 GB 保底，最多約 3 人同時保底。

**WSL VM（`6` WSL）**
- `e` 編輯 VM 的記憶體（16–124 GB）、處理器數、swap。存檔後需重啟 WSL 才生效。
- `R` 重啟 WSL：**會中斷所有人的連線與程式**，約 90 秒後自動恢復。先確認沒人在跑重要工作（看 `3` Kernels）。

**GPU**：不設配額。有人佔滿 VRAM 時，在 `3` Kernels 找到該 kernel，先聯絡本人，必要時按 `s` 停止。

**NPU**：自動排隊，每人最多 4 個工作，不需設定。`5` Hardware 可看狀態；顯示 worker down 時見第 7 節。

**停止 kernel**：`3` Kernels 選取 → `s` → `y`。只在影響他人時使用，並告知本人。

## 6. 稽核紀錄

`9` Audit 列出誰在何時做了什麼（新增使用者、停用、金鑰、策略、WSL），以及結果成功或失敗。完整紀錄在 `/var/log/compute-mgr/audit.jsonl`。看到不是你做的操作，先檢查管理員名單。

## 7. 故障排除

| 狀況 | 處理 |
|---|---|
| cm-top 打不開或顯示無法連線 | `ssh -p 2200 user@192.168.1.10 'sudo systemctl restart compute-mgrd'` |
| 所有人都連不上 SSH | 伺服器 Windows 開機後約 1–2 分鐘 WSL 才會起來；仍不行就在 Windows 執行 `wsl -d compute` |
| NPU 顯示 worker down | Windows 上（系統管理員 PowerShell）：`Start-ScheduledTask cm-npu-worker` |
| 使用者 `Permission denied (publickey)` | Users → 該人 → 確認金鑰清單有那把指紋 |
| 記憶體一直不足 | 看 `8` History 誰長期用量高；調整策略或請對方分批處理 |

## 8. 給使用者的文件

伺服器上的 `/opt/compute/` 有：
- `README.md`：使用指南
- `USER-SETUP.zh-TW.md`：第一次連線的逐步教學
- `AGENT-SETUP.md`：給 AI agent 自動設定用

新使用者開帳號時，把《第一次連線》一併傳給對方。
